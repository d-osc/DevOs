# @dev-os/core — React GTK and desktop API for GJS

Local renderer for GTK 3, written in strict TypeScript. TSX produces Gtk widgets through React's reconciler;
the application runs in GJS. The build uses React 19.2.8, react-reconciler 0.33.0
and esbuild. These versions are pinned because the reconciler host contract is
experimental. This library has not been published to npm.

## Build and run

From the project root, run `npm ci` and `npm run build`. On Windows, use
`./dev.ps1 demo`; on Linux with a graphical session, use `npm run demo`.
`npm run typecheck` checks types without a graphical session. Every build checks
types and emits declarations under `dist/types/` with `dist/core.d.ts` as
the entry point. The native types come from `@girs` packages generated by
[ts-for-gir](https://github.com/gjsify/ts-for-gir).
`npm run watch` rebuilds on changes and checks types before each rebuild. For edits
to type-only files, run `npm run typecheck:watch` in a second terminal. Restart the
running application after a build; watch does not reload the application.

Import React and hooks from **the same library** as the renderer:

```tsx
import Gtk from 'gi://Gtk?version=3.0';
import {React, createRoot, Box, Label, Button, useState} from '@dev-os/core';

function Counter() {
    const [count, setCount] = useState(0);
    return <Box orientation="vertical" spacing={12} borderWidth={24}>
        <Label>Count: {count}</Label>
        <Button onClicked={() => setCount(value => value + 1)}>Add</Button>
    </Box>;
}

// Inside a Gtk.Application's activate handler:
const window = new Gtk.ApplicationWindow({application, title: 'Counter'});
const root = createRoot(window);
root.render(<Counter />);
window.connect('delete-event', () => { root.unmount(); return false; });
window.show();
```

For a complete runnable Gtk.Application, see `examples/Counter.tsx`.
Add your TSX entry to `tools/build/build.ts`, and output the entry under `dist/`.
The `@dev-os/core` alias maps to source in `tsconfig.json` and is rewritten
to the external `./core.js` bundle by the build plugin. Importing a
second bundled copy of React causes invalid hook calls. GI modules remain external
because GJS supplies them at runtime. Node.js is only needed for the build.

Props are exported as `BoxProps`, `LabelProps`, `ButtonProps`, `EntryProps`, etc.
Handlers infer native widgets (for example `Gtk.Entry` in `onChanged`); refs
must match the component's native widget type:

```tsx
const labelRef = React.createRef<Gtk.Label>();
const view = <Label ref={labelRef}>Ready</Label>;
```

`tests/props.types.test.tsx` verifies that incorrect props, DOM events, wrong
ref types and non-native root containers are rejected. The runtime supports the
checked public component API; all desktop services and tests are TypeScript / GJS.
The build tool is TypeScript too, and uses Node 22.18 (22.x) or Node 24+.

## Components

| Component | GTK widget | Common props |
| --- | --- | --- |
| `Box` | Gtk.Box | `orientation`, `spacing`, `homogeneous` |
| `Label` | Gtk.Label | text children or `text`, `wrap`, `selectable`, `xalign`, `ellipsize` |
| `Button` | Gtk.Button | text children or one widget, `onClicked` |
| `Entry`, `SearchEntry` | Gtk.Entry / Gtk.SearchEntry | `text`, `placeholder`, `editable`, `maxLength`, `onChanged`, `onActivate` |
| `Switch` | Gtk.Switch | `active`, `onActiveChanged` |
| `CheckButton` | Gtk.CheckButton | text children, `active`, `onToggled` |
| `Image` | Gtk.Image | `iconName`, `iconSize` (GTK enum) |
| `Separator` | Gtk.Separator | `orientation` |
| `ScrolledWindow` | Gtk.ScrolledWindow | one child |
| `ListBox` | Gtk.ListBox | `selectionMode`, `activateOnSingleClick`, `onRowSelected`, `onRowActivated` |
| `ListBoxRow` | Gtk.ListBoxRow | one child |
| `FlowBox` | Gtk.FlowBox | `selectionMode`, `activateOnSingleClick`, `onChildActivated`, `onSelectedChildrenChanged`, line limits and spacing |
| `FlowBoxChild` | Gtk.FlowBoxChild | one child |
| `DrawingArea` | Gtk.DrawingArea | `onDraw(widget, cairoContext)` returning a boolean |

Common props: `ref`, `className`, `id`, `tooltip`, `visible`, `sensitive`,
`hexpand`, `vexpand`, `halign`, `valign`, `widthRequest`, `heightRequest`,
`marginTop`, `marginBottom`, `marginStart`, `marginEnd`.
Containers also accept `borderWidth`. GTK-specific properties are checked;
unknown props and unsupported host elements report errors.

Images also accept `gicon` (a Gio.Icon) and `pixelSize`; `gicon` takes precedence
over `iconName`. ScrolledWindow supports `minContentHeight`, `hscrollbarPolicy`
and `vscrollbarPolicy`. ListBox children should be explicit ListBoxRow elements.
DrawingArea uses the native Cairo context supplied by GTK; its handler can draw
custom graphics and returns `false` to continue normal signal handling.

For children of a Box, use `pack="start"` (default), `pack="end"` or
`pack="center"`, with `expand`, `fill` and `padding`. Only one center child is
allowed. Orientation accepts `horizontal` / `vertical`; alignment accepts
`start`, `end`, `center`, `fill`, `baseline` or a Gtk.Align enum.

Labels accept strings, numbers and arrays of text, including `Count: {count}`.
Buttons accept either text or one child widget. Gtk.Bin containers accept one
child; wrap multiple children in a Box. Use keys for changing lists.

## Events, refs and lifecycle

Handlers receive native GTK signal arguments, beginning with the widget:

```jsx
<Entry text={name} onChanged={entry => setName(entry.get_text())} />
<CheckButton active={checked} onToggled={button => setChecked(button.active)}>Enabled</CheckButton>
```

There are no DOM SyntheticEvents. Controlled prop commits suppress their own
signals; user changes call the latest handler. Removing a handler disconnects it.
Refs expose actual Gtk widgets. Native events commit state updates synchronously;
timer and effect updates run on GLib's main loop.

`createRoot(emptyGtkContainer, {onError})` creates one root per container.
`root.render(element)` commits synchronously. `root.unmount()` is idempotent,
removes native children and runs effect cleanup. Call it before destroying the
container. A disposed root cannot render again; create a new root instead.
`flushSync(callback)` is available for external imperative state updates.

Use `useEffect` to subscribe to D-Bus, GTK or GLib services, and return a cleanup
callback. The runtime supplies `setTimeout`, `clearTimeout`, `queueMicrotask` and
`performance.now`; use GLib for repeating timers, as the demo does.

## Scope and validation

This is a starting library for native desktop UI, not an HTML/CSS converter.
GTK CSS applies through Gtk.CssProvider; `style={{...}}`, browser APIs, React DOM,
SSR/hydration, React Native APIs and automatic state-preserving hot reload are
not implemented. Advanced features such as Activity, portals, transitions and
Suspense are not part of the tested API.

`./dev.ps1 smoke` starts a real private headless Wayland session and tests hooks,
events, context, refs, keyed ordering, controlled props, packing, visibility,
text/icon transitions and effect cleanup. Desktop UI tests additionally check
search/empty states, session confirmation, actions, clock/message state, list
ordering and drawing callbacks. All shell UI is now implemented in TSX; native
adapters handle Wayland windows and system services. The complete desktop and
demo are also exercised through compositor shortcuts and real app launches.
Runtime requirements match the main shell: GJS >= 1.74, GLib >= 2.80, GTK 3.24;
desktop layer surfaces additionally require gtk-layer-shell and labwc.

Primary references: [React reconciler host contract](https://github.com/facebook/react/tree/v19.2.0/packages/react-reconciler),
[GJS ES modules](https://gjs.guide/guides/gjs/esm.html),
[GTK 3 widget APIs](https://docs.gtk.org/gtk3/).


### Shared application header

Use `mountWindowHeader` for ordinary application windows after `createRoot(window)`
and before the window is first shown. Layer-shell panels and overlays keep their
own surface controls.

```tsx
import {createRoot, mountWindowHeader} from '@dev-os/core';

const root = createRoot(window);
root.render(<App />);
const header = mountWindowHeader(window, {
    title: 'My app',
    iconName: 'applications-development-symbolic',
    windowIconName: 'applications-development',
});
// Before destroying the window:
root.unmount();
header.destroy();
```

The shared header includes an icon from the active GTK icon theme, native
minimize/maximize/close controls and the compositor's right-click window menu.
Theme extensions override `.app-titlebar` styles at APPLICATION priority.

## Desktop and extension API

The same package exports `UIRuntime`, `UIExtension`, `UIContext`, `Cleanup`, settings and manifest types, `Config`, `Command`, `WindowControls`, and `SettingsPages`. The host supplies services through `UIContext`; extensions return cleanup from `activate`.

## Pack a standalone library

Run `npm run core:pack` from the repository root. The archive is written to `build/core-package/dev-os-core-0.3.6.tgz`. Install it in another project with `npm install /path/to/dev-os-core-0.3.6.tgz`.

The package includes a single ESM bundle containing React, React Reconciler, Scheduler, the GTK renderer, timers, and UIRuntime, plus all referenced declarations and third-party licenses. Type dependencies are declared in the package manifest and installed by npm. Native GTK 3, GJS and required GI libraries must be available on the Linux host. The library is intended for GJS, not Node.js or browsers.

Import React, hooks, widgets and extension types from `@dev-os/core` to share the bundled React instance. Extensions running inside Dev OS should continue using `npm run extension:package` so they share the desktop runtime.

## Native Gio and GLib

```ts
import {Gio, GLib} from '@dev-os/core';

const file = Gio.File.new_for_path(GLib.get_home_dir());
```

These exports use GJS's `gi://Gio` and `gi://GLib` modules. The native libraries remain supplied by the Linux host; their TypeScript definitions are package dependencies.

## GI namespaces

All GI namespaces used by this repository are exported: `Gtk` (3.0), `Gdk` (3.0), `GtkLayerShell` (0.1), `Gio`, `GLib`, `GObject`, `Pango`, `GLibUnix`, `Soup` (3.0), `Vte` (2.91), and `WebKit2` (4.1).

```ts
import {Gtk, Gdk, GtkLayerShell, Gio, GLib, GObject, Pango, GLibUnix, Soup, Vte, WebKit2} from '@dev-os/core';
```

The bundle loads these native namespaces when imported; all must be installed on the Linux host. This covers the repository GI dependencies, not every possible namespace provided by system GIR packages.

## Source layout

- `view.ts`: React host components, hooks and props exports.
- `renderer.ts`: reconciler, widget updates, `createRoot` and `flushSync`.
- `window-header.ts`: window titlebar view and lifecycle helper.
- `index.ts`: the public `@dev-os/core` API.

## Additional views

| Group | Components |
| --- | --- |
| Layout and pages | Grid, Overlay, Stack, Notebook, Paned |
| Containers | Frame, Expander, Revealer, EventBox, Viewport, ButtonBox, HeaderBar, ActionBar |
| Buttons | ToggleButton, LinkButton, MenuButton |
| Status | Spinner, ProgressBar, LevelBar |
| Input | SpinButton, TextView, ComboBoxText |

All views expose native GTK refs and typed props/events. Entry supports `password` and `activatesDefault`; ScrolledWindow supports minimum and maximum content sizes. Additional hooks include `useId`, `useTransition`, `useDeferredValue`, `useSyncExternalStore`, and `useDebugValue`.

Child layout props are interpreted by the parent: Grid uses `gridLeft`, `gridTop`, `gridWidth`, `gridHeight` (integer coordinates, positive spans); Stack uses `pageName` and `pageTitle`; Notebook uses `tabLabel`; Overlay has one main child and extra children marked `overlay`; Paned accepts two children with `resize` and `shrink`. HeaderBar and ActionBar support `pack="start"`, `pack="end"`, and one `pack="center"` child. Ordinary single-child containers accept one child; wrap siblings in Box.

`TextView` connects `onChanged` to its text buffer and passes the native text view to the callback. `ComboBoxText` takes `items={[{id: 'one', text: 'One'}]}` and `activeId`. Controlled values suppress callbacks during React commits and disconnect callbacks when removed or unmounted.

`visibleChildName` and `currentPage` are applied after child mounting so initial page selection works. Use stable, unique `pageName` values in Stack. GTK model-based views such as TreeView and top-level dialogs are not provided by these JSX wrappers yet; the exported native Gtk namespace remains available.

Run the native view tests with `gjs -m dist/view-test.js` after a build, on Linux with a GTK display.

## GIR type exports

Import types from `@dev-os/core` without importing `@girs/*` directly:

```ts
import type {GtkTypes, GioTypes, GdkTypes, GdkPixbufTypes, Cairo} from '@dev-os/core';

let button: GtkTypes.Button;
let file: GioTypes.File;
let event: GdkTypes.EventButton;
let pixbuf: GdkPixbufTypes.Pixbuf;
let context: Cairo.Context;
```

Type-only namespace aliases cover all 20 GIR packages installed in this repository: `AtkTypes`, `CairoGITypes`, `Freetype2Types`, `GdkTypes`, `GdkPixbufTypes`, `GioTypes`, `GjsTypes`, `GLibTypes`, `GLibUnixTypes`, `GModuleTypes`, `GObjectTypes`, `GtkTypes`, `GtkLayerShellTypes`, `HarfBuzzTypes`, `JavaScriptCoreTypes`, `PangoTypes`, `SoupTypes`, `VteTypes`, `WebKit2Types`, `XlibTypes`. GJS-specific exports also include `Cairo`, `SystemTypes`, `GettextTypes`, and `GiTypes`. The original native namespace exports such as `Gtk` remain usable as both values and types.

These are TypeScript exports and introduce no additional native runtime imports. The npm manifest declares each underlying GIR package as a dependency so the declarations also resolve after installation outside this repository.

## Shared services

`Listeners` centralizes subscription, emission, optional subscriber error reporting, and cleanup. `readText`, `readJson`, and `writeJson` provide UTF-8 file access and private atomic JSON writes. `moveTabItem` and `reconcileRemovedTab` share the Files/Terminal transfer and active-tab selection rules. Extension lifecycle implementation is in `extension-runtime.ts`. Applications import these services, GUI views, native namespaces and GIR types through `@dev-os/core`.
