# Theme

Dev OS has two color themes, each with a **Dark** and a **Light** variant: **VS Code 2026**
(the default *2026 Dark* / *2026 Light* of Visual Studio Code, the default) and **GitHub**
(*GitHub Dark Default* / *GitHub Light Default*). An **Auto** mode switches between the
Dark and Light variant by time of day. Auto is the default.

Settings → Theme shows a preview of both variants, the choice of color theme (VS Code
2026 or GitHub), the choice of Auto / Dark / Light, and the two Auto switch times. The saved
values are `family` (`vscode` or `github`), `mode` and the schedule; an unknown `family` reads as `vscode`. Apply saves the `org.devos.theme`
preferences and every window restyles at once without a restart: panel,
launcher, Settings, Files, Task View, terminal windows (including their VTE
colors), the embedded editor (Monaco), the wallpaper, the lock screen and the
sign-in screen. Reset discards unapplied choices; invalid times disable Apply.

## Auto

Auto uses the local time: **Light from 07:00 until 19:00, Dark the rest of the
day.** Both times are editable (`HH:MM`, 24-hour). Equal or malformed times are
rejected in the page and fall back to the defaults when read from disk. A
schedule such as Light 20:00 → 06:00 (wrapping past midnight) works.

The theme extension re-evaluates the clock when the next switch time arrives
(a GLib timer set for that moment) and at least once a minute, which also picks
up clock and time-zone changes. It also re-evaluates when the system resumes
from sleep (logind `PrepareForSleep(false)`, the signal `packages/runtime/sleep.ts`
already uses). The schedule is fixed times; sunrise/sunset are not computed.
`resolveTheme(mode, now, schedule)` and `msUntilSwitch(...)` in
`packages/core/theme.ts` are pure and unit-tested (`tests/theme.test.ts`).

The sign-in screen runs before any settings exist, so it follows the default
Auto schedule.

## Where the colors come from

`extensions/org.devos.theme/vscode/` holds the copied VS Code 1.143.1 theme
files (`2026-dark.json`, `2026-light.json` and the `dark_modern.json` / `light_modern.json` they
include) and `vscode/github/` the GitHub theme 6.3.5 files; `NOTICE.md` has the MIT notices.
`node tools/theme/generate-palette.mjs` reads them and writes
`packages/core/theme-palette.ts`, which records for every token the VS Code key
it was copied from (`paletteSources`) and the sixteen terminal ANSI colors and
terminal foreground (VS Code workbench defaults, which the theme files do not
override). `tests/theme.test.ts` checks every copied color against the JSON files.

Semantic tokens are exposed to GTK CSS as `@define-color dv_*` (surfaces
`dv_s0…s7`, lines `dv_line0…3`, text `dv_fg`, `dv_fg_strong`, `dv_fg_muted`,
`dv_fg_dim`, `dv_accent`, `dv_accent_fg` (accent used as text), `dv_on_accent`,
status colors and tints derived with `mix()`), generated by `themeTokens(name)`
and prepended to `style.css`. `style.css` contains no literal colors:
`tests/theme-css.test.ts` fails on any `#hex`/`rgb()` and on any `@dv_` name
missing from either theme, compiles both stylesheets in GTK, and checks WCAG AA
(≥ 4.5:1) in every family and variant for body, muted and accent text on the surfaces they are used on, for
text on the accent fill, for the terminal foreground, and for the bold prompt
colors (green, red, blue). Dark and Light are not hand-tuned per selector: the same
CSS is used with a different token set. `tools/theme/tokenize-css.mjs` is the one-time
converter that rewrote the old literal colors into tokens.

Code that draws with Cairo or VTE reads `activePalette()`, and subscribes with
`onThemeChange()` to redraw (terminal tabs, editor, wallpaper, snap layouts).

## What was removed

* The Graphite / Ocean / Plum palettes and the five accent presets, the custom
  accent color and "Use Desktop accent".
* The Terminal color schemes Midnight / Slate / Paper (the terminal follows the
  theme). On Dark the terminal draws bold text in the bright ANSI colors
  (`bold_is_bright`), so the bold prompt colors (green user, red root, blue path)
  stay readable on the dark background.
* `accent` and `background` in `config.json` and the Desktop settings fields for
  them; the wallpaper base color follows the theme (Background → "Use theme
  background color"; a custom color still overrides it).

## Migration

* Saved Theme settings written before (`settingsVersion` 1) are migrated on read
  (`packages/extensions/migrations.ts`): Ocean and Plum become **Dark**,
  Graphite (the old default), missing or unknown values become **Auto**. Nothing
  throws. Terminal settings drop `scheme`.
* `config.json` files that still contain `accent` or `background` load fine; the
  keys are ignored and are not written back.

## Validation

`npm run build`, then in a GTK session `gjs -m dist/theme-test.js`,
`dist/theme-css-test.js`, `dist/theme-settings-test.js`,
`dist/terminal-settings-test.js` and `dist/lock-test.js`. Tests that load
`style.css` use `tests/theme-helper.ts`; set `DEV_OS_TEST_THEME=light` to render
them with the Light theme.
